# Этап 2. Класс HookPatch, логирование и тест перехвата

## 1. Что требуется

По заданию лабораторной работы на этапе 2 нужно:

1. разработать в тестовой программе класс `HookPatch` с методами
   установки и отката изменений;
2. разработать функцию логирования, на которую передаётся управление
   при вызове выбранной API-функции;
3. протестировать класс: установить хук, вызвать функцию, снять хук,
   вызвать снова.

DLL, инжектор и командная строка — это этапы 3–4.

## 2. Что сделано

```
stage2/testapp/
    HookPatch.h      — объявление класса
    HookPatch.cpp    — Install/Remove и трамплин
    testapp.cpp      — сценарий проверки
    data/hello.txt   — файл для CreateFileW
    testapp.vcxproj  — проект x64 Debug/Release
```

Класс `HookPatch` — не набор глобальных функций, а объект с состоянием:

| Метод | Назначение |
|---|---|
| `HookPatch(target, hook, patchSize)` | запоминает адрес функции, адрес хука и размер патча |
| `Install()` | сохраняет оригинал, ставит `jmp`, строит трамплин |
| `Remove()` | возвращает оригинальные байты и освобождает трамплин |
| `Trampoline()` | указатель на трамплин, через него вызывается оригинал |
| `IsInstalled()` | установлен ли хук |
| `UsesAbsoluteJump()` | какой режим выбран: `E9` или `FF 25` |
| `PatchSize()` | сколько байт перезаписано |

Глобального `SIZE 11` нет: размер передаётся в конструктор.

## 3. Почему для CreateFileW выбран абсолютный переход

На этапе 1 для `CreateFileW` измерен пролог длиной 13 байт:

```text
40 53                  push rbx              -> 2
48 83 EC 50            sub rsp,50h           -> 6
8B 84 24 88 00 00 00   mov eax,[rsp+88h]     -> 13
```

Для относительного `E9 rel32` этого достаточно. Но `E9` достаёт
только на ±2 ГБ, а `testapp.exe` и `kernelbase.dll` на x64 находятся
далеко друг от друга. Поэтому `HookPatch::BuildNewBytes()` сначала
проверяет, влезает ли смещение в `int32_t`:

- если да — ставит `E9 rel32` + NOP;
- если нет и `patchSize >= 14` — ставит абсолютный
  `FF 25 00 00 00 00` + 8 байт адреса;
- иначе `Install()` возвращает `false`.

В тесте используется абсолютный режим и размер **16 байт**:

```text
FF 25 00 00 00 00   ; jmp qword ptr [rip+0]
<8 байт адреса HookedCreateFileW>
90 90               ; добиваем до 16 байт
```

16 байт — это 13 байт пролога плюс `mov r10d,eax` (3 байта), то есть
целая граница инструкции. Трамплин:

```text
16 байт оригинала
FF 25 00 00 00 00
<8 байт адреса target + 16>
```

Итого `16 + 14 = 30` байт; `HookPatch` выделяет `patchSize + 14`.

Тест выводит выбранный режим:

```text
[hook] installed: absolute, 16 bytes
```

## 4. Алгоритм Install/Remove

### Install

1. Проверить `target`, `hook`, `patchSize` (5–32).
2. Сохранить оригинальные байты в `oldBytes_`.
3. Собрать новые байты (`E9` или `FF 25`).
4. Выделить трамплин `patchSize + 14`, скопировать туда оригинал
   и добавить absolute jump на `target + patchSize`.
5. `VirtualProtect` → записать новые байты в `target`.
6. `FlushInstructionCache`.
7. Вернуть исходную защиту страницы.

Сначала готовится трамплин и только потом патчится код — в этот
короткий момент вызова перехваченной функции не будет.

### Remove

1. `VirtualProtect` → вернуть `oldBytes_` в `target`.
2. `FlushInstructionCache`.
3. Вернуть защиту.
4. `VirtualFree` трамплина.
5. `installed_ = false`.

Деструктор вызывает `Remove()`, поэтому забыть снять хук нельзя.

## 5. Функция логирования

На этапе 2 используется типизированная обёртка с той же сигнатурой,
что и `CreateFileW`:

```cpp
HANDLE WINAPI HookedCreateFileW(...) {
    SYSTEMTIME time{};
    GetLocalTime(&time);
    wprintf(L"[%02d:%02d:%02d] CreateFileW(%ls)\n",
            time.wHour, time.wMinute, time.wSecond, fileName);

    auto original = reinterpret_cast<CreateFileW_t>(g_patch->Trampoline());
    return original(fileName, ...);
}
```

Она:

- печатает имя функции и время;
- вызывает оригинал через трамплин;
- возвращает результат оригинальной функции.

Логирование идёт в консоль, **не в файл через CreateFileW**, иначе
получилась бы рекурсия.

Ассемблерный обработчик на этом этапе не нужен: сигнатура `CreateFileW`
известна. Он понадобится на этапе 4 для универсального режима `-func`,
где имя функции задаётся строкой.

## 6. Сценарий теста

1. Вызов `CreateFileW` до установки хука — лога нет.
2. Создаётся `HookPatch` для `kernelbase!CreateFileW`, размер 16.
3. `Install()`.
4. Пять вызовов `CreateFileW` — каждый должен дать строку с временем.
5. `Remove()`.
6. Ещё один вызов — лога нет, оригинальная функция работает.

Фактический вывод:

```text
target CreateFileW = 00007FFDD1102B90
[baseline]
[hook] installed: absolute, 16 bytes
[19:03:01] CreateFileW(data\hello.txt)
[19:03:01] CreateFileW(data\hello.txt)
[19:03:01] CreateFileW(data\hello.txt)
[19:03:01] CreateFileW(data\hello.txt)
[19:03:01] CreateFileW(data\hello.txt)
[hook] removed
[after remove]
done
```

## 7. Как повторить

1. Открыть `trspo-lab1.sln`.
2. Выбрать `Debug | x64`.
3. В Solution Explorer правой кнопкой по `stage2_testapp` →
   `Set as Startup Project`.
4. `F5`.

Рабочая директория проекта — `stage2\testapp`, поэтому
`data\hello.txt` находится. При запуске из консоли:

```powershell
cd stage2\testapp
..\..\bin\x64\Debug\stage2_testapp.exe
```
