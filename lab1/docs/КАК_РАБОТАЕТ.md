## 1. Что получилось

В проекте три части:

```text
src/hook/       → hook.dll
src/monitor/    → monitor.exe
src/victim/     → victim.exe
```

### `hook.dll`

Главная библиотека. Она:

- загружается внутрь чужого процесса;
- подключается к `monitor.exe` через именованный канал;
- умеет ставить inline-хук на функцию;
- умеет скрывать файл через три хука файловых функций.

### `monitor.exe`

Управляющая программа. Она:

- разбирает командную строку;
- находит целевой процесс по PID или имени;
- загружает `hook.dll` в этот процесс;
- создаёт канал;
- отправляет команду `-func` или `-hide`;
- печатает ответы DLL.

### `victim.exe`

Тестовая программа. Она нужна только для проверки:

- перечисляет текущий каталог;
- ищет в нём `secret.txt`;
- пытается открыть файл;
- повторяет это 20 раз.

В поставку лабораторной `victim.exe` не входит, но с ним удобно
показывать работу.

## 2. Быстрый запуск

Сборка:

```powershell
msbuild trspo-lab1.sln /t:Rebuild /p:Configuration=Debug /p:Platform=x64
```

Или в Visual Studio 2026: открыть `trspo-lab1.sln`, выбрать
`Debug | x64`, нажать `Ctrl+Shift+B`.

Мониторинг:

```powershell
$victim = Start-Process bin\x64\Debug\victim.exe -PassThru `
    -WorkingDirectory src\victim\data
Start-Sleep -Milliseconds 400
bin\x64\Debug\monitor.exe -pid $victim.Id -func CreateFileW
```

Скрытие:

```powershell
$victim = Start-Process bin\x64\Debug\victim.exe -PassThru `
    -WorkingDirectory src\victim\data
Start-Sleep -Milliseconds 400
bin\x64\Debug\monitor.exe -pid $victim.Id -hide `
    (Resolve-Path src\victim\data\secret.txt).Path
```

`victim` не принимает аргументов: он работает в своём рабочем каталоге,
поэтому данные лежат в `src\victim\data`. `victim` ждёт 3 секунды,
поэтому после запуска `monitor` нужно дать ему время вывести результат.

## 3. Ключевые понятия

### Процесс и виртуальная память

У каждого процесса Windows своё виртуальное адресное пространство.
Адрес `0x7FF...` в одном процессе и такой же адрес в другом — это
разные физические страницы. Поэтому нельзя просто взять указатель из
одного процесса и использовать его в другом.

### Модуль

Модуль — это загруженный в процесс `.exe` или `.dll`. У каждого
модуля есть база, например `0x7FFDD1100000`. Адрес функции — это
база модуля плюс смещение (RVA).

В работе функции берутся из `kernelbase.dll`:

```cpp
HMODULE kernelbase = GetModuleHandleW(L"kernelbase.dll");
void* target = reinterpret_cast<void*>(
    GetProcAddress(kernelbase, "CreateFileW"));
```

### PID

PID — числовой идентификатор процесса. `monitor.exe` получает его
из `-pid` или ищет по имени через Toolhelp32.

### Вызов WinAPI и пролог

У каждой функции есть начало — пролог. Там она сохраняет регистры,
выделяет место под локальные переменные и делает другую подготовку.
Inline-хук заменяет первые байты этой функции переходом на свой код.

### Трамплин

Трамплин — кусок памяти, куда копируются оригинальные первые
инструкции функции. После них стоит переход обратно в функцию.
Получается:

```text
вызов функции
   ↓
патч в начале функции
   ↓
обработчик
   ↓
трамплин: оригинальные инструкции + переход в функцию после патча
```

Так обработчик может сделать что-то своё и всё равно вызвать
оригинальную функцию.

### Соглашение вызова x64

В Windows x64 первые четыре аргумента функции передаются в
регистрах `RCX`, `RDX`, `R8`, `R9`. Остальные — через стек.
Перед вызовом функции нужно выделить 32 байта «теневое пространство»
(shadow space), даже если у функции меньше четырёх аргументов.

Это важно для ассемблерного обработчика: он вызывает `Status()` и
обязан соблюсти это правило.

## 4. Общая схема

```text
monitor.exe
    │
    │ 1. OpenProcess
    │ 2. VirtualAllocEx + WriteProcessMemory
    │ 3. CreateRemoteThread(LoadLibraryW)
    ▼
victim.exe
    │
    │ 4. загружает hook.dll
    ▼
hook.dll
    │
    │ 5. CreateFileW(pipe) + HELLO
    ▼
monitor.exe
    │
    │ 6. -func CreateFileW  или  -hide <path>
    ▼
hook.dll
    │
    │ 7. OK
    │ 8. LOG ... при каждом вызове
    ▼
monitor.exe
```

Порядок в коде немного другой: `monitor` сначала загружает DLL, а
потом создаёт канал. DLL умеет ждать канал до 5 секунд, поэтому
гонка не страшна.

## 5. DLL-инъекция

### Зачем загружать DLL

Код можно выполнить в чужом процессе разными способами. Самый
простой и понятный — заставить процесс загрузить свою DLL. Тогда
код DLL выполняется в адресном пространстве процесса и может
работать с его функциями.

### Как это делает `monitor`

Основная функция — `InjectDll` в
[`src/monitor/monitor.cpp`](../src/monitor/monitor.cpp).

Сначала открывается процесс:

```cpp
HANDLE process = OpenProcess(
    PROCESS_CREATE_THREAD | PROCESS_QUERY_INFORMATION |
        PROCESS_VM_OPERATION | PROCESS_VM_WRITE | PROCESS_VM_READ,
    FALSE, pid);
```

Права нужны конкретные:

| Право | Зачем |
|---|---|
| `PROCESS_CREATE_THREAD` | создать удалённый поток |
| `PROCESS_QUERY_INFORMATION` | узнать результат загрузки |
| `PROCESS_VM_OPERATION` | выделить и освободить память |
| `PROCESS_VM_WRITE` | записать путь к DLL |
| `PROCESS_VM_READ` | прочитать память при необходимости |

Затем находится адрес `LoadLibraryW` в `kernel32.dll`:

```cpp
HMODULE kernel32 = GetModuleHandleW(L"kernel32.dll");
const auto loadLibrary = reinterpret_cast<LPTHREAD_START_ROUTINE>(
    GetProcAddress(kernel32, "LoadLibraryW"));
```

`LoadLibraryW` — это функция, которая принимает один аргумент:
указатель на широкую строку с путём к DLL. Она подходит на роль
функции удалённого потока.

Дальше:

```cpp
void* remotePath = VirtualAllocEx(process, nullptr, pathBytes,
                                  MEM_COMMIT | MEM_RESERVE,
                                  PAGE_READWRITE);
WriteProcessMemory(process, remotePath, dllPath.c_str(), pathBytes, nullptr);

HANDLE thread = CreateRemoteThread(process, nullptr, 0, loadLibrary,
                                   remotePath, 0, nullptr);
```

Что происходит:

1. В чужом процессе выделяется память под строку с путём.
2. В эту память копируется путь `hook.dll`.
3. Создаётся поток, который начинает выполнение с `LoadLibraryW`.
4. Аргумент потока — адрес строки в чужом процессе.

После запуска `monitor` ждёт поток:

```cpp
WaitForSingleObject(thread, 10000);
GetExitCodeThread(thread, &exitCode);
```

`LoadLibraryW` возвращает `HMODULE` — базу загруженной DLL. Этот
`HMODULE` становится кодом завершения потока. Если он не ноль,
загрузка успешна.

В конце освобождается память и закрываются handle:

```cpp
VirtualFreeEx(process, remotePath, 0, MEM_RELEASE);
CloseHandle(thread);
CloseHandle(process);
```

### Почему адрес `LoadLibraryW` одинаковый

`kernel32.dll` — системная библиотека, и в 64-битных процессах
она обычно отображается по одинаковому адресу. Поэтому адрес
`LoadLibraryW`, полученный в `monitor.exe`, подходит и для
целевого процесса. Для учебной работы этого достаточно.

### Ограничения инъекции

- Нужны права на открытие процесса. Чужой процесс с более высоким
  уровнем целостности открыть не получится.
- `monitor` и target должны быть одной битности. 32-битный monitor
  не загрузит 64-битную DLL в 64-битный процесс.
- Если DLL не загрузилась, `GetExitCodeThread` вернёт 0; причина
  может быть в зависимостях DLL или в неправильном пути.

## 6. Именованный канал и протокол

### Зачем канал

После инъекции `monitor` и DLL находятся в разных процессах. Им
нужно передавать команды и получать ответы. Для этого используется
именованный канал Windows (named pipe).

Имя канала:

```cpp
constexpr const wchar_t* kPipeName = L"\\\\.\\pipe\\lab1_monitor";
```

`\\.\pipe\` — стандартный префикс для локальных каналов.

### Кто создаёт канал

`monitor` создаёт серверную сторону:

```cpp
HANDLE pipe = CreateNamedPipeW(
    kPipeName,
    PIPE_ACCESS_DUPLEX,
    PIPE_TYPE_MESSAGE | PIPE_READMODE_MESSAGE,
    1,
    kBufferSize,
    kBufferSize,
    0,
    nullptr);
```

- `PIPE_ACCESS_DUPLEX` — можно и читать, и писать;
- `PIPE_TYPE_MESSAGE` — сообщения сохраняют границы;
- `PIPE_READMODE_MESSAGE` — читать целыми сообщениями;
- `1` — максимум один экземпляр канала;
- `kBufferSize` — размер буфера.

DLL создаёт клиентскую сторону:

```cpp
HANDLE pipe = CreateFileW(kPipeName,
                          GENERIC_READ | GENERIC_WRITE,
                          0, nullptr, OPEN_EXISTING, 0, nullptr);
```

Затем переводит свой конец в message-режим:

```cpp
DWORD mode = PIPE_READMODE_MESSAGE;
SetNamedPipeHandleState(pipe, &mode, nullptr, nullptr);
```

В коде есть повторные попытки: DLL может попытаться открыть канал
раньше, чем `monitor` успеет вызвать `ConnectNamedPipe`. Поэтому
`ConnectToLoader` делает до 50 попыток с паузой 100 мс, а установку
режима повторяет до 20 раз по 50 мс.

### Формат сообщений

Все сообщения — обычные C-строки, заканчивающиеся нулём. Максимум
1024 байта. Внутри может быть UTF-8 для пути.

### Протокол

| Шаг | Кто | Сообщение | Что значит |
|---:|---|---|---|
| 1 | DLL → monitor | `HELLO 1234` | DLL загрузилась, готова |
| 2 | monitor → DLL | `-func CreateFileW` | включить мониторинг |
| 3 | DLL → monitor | `OK hooked` | хук установлен |
| 4 | DLL → monitor | `LOG 19:45:12 CreateFileW` | был вызов функции |
| 5 | monitor → DLL | `-hide C:\...\secret.txt` | скрыть файл |
| 6 | DLL → monitor | `OK hidden` | три хука установлены |
| 7 | DLL → monitor | `ERROR ...` | что-то пошло не так |

Пример `-func`:

```text
[monitor] pipe connected
[monitor] <- HELLO 4328
[monitor] <- OK hooked
[monitor] LOG 19:43:28 CreateFileW
[monitor] LOG 19:43:29 CreateFileW
...
[monitor] target disconnected
[monitor] done
```

### Почему `HELLO` проверяется

`RunProtocol` сравнивает сообщение с ожидаемым:

```cpp
char expectedHello[64];
sprintf_s(expectedHello, sizeof(expectedHello), "HELLO %lu", pid);
if (message != expectedHello) {
    ...
}
```

Это защита от ситуации, когда к каналу подключился не тот процесс
или старая DLL.

### Почему `LOG` может прийти раньше `OK`

Если целевая программа вызывает функцию сразу после установки
хука, `LOG` может оказаться в канале раньше, чем `OK hooked`.
Поэтому `RunProtocol` читает сообщения в цикле, печатает всё, что
пришло, и ждёт сообщение, начинающееся с `OK` или `ERROR`.

В режиме `-hide` после `OK hidden` канал закрывается, а хуки
остаются в процессе. В режиме `-func` `monitor` читает `LOG`, пока
целевой процесс не завершится.

## 7. Класс HookPatch

Файлы:

- [`src/hook/HookPatch.h`](../src/hook/HookPatch.h)
- [`src/hook/HookPatch.cpp`](../src/hook/HookPatch.cpp)

### Задача класса

`HookPatch` отвечает за один хук:

- сохранить оригинальные байты;
- записать переход на обработчик;
- построить трамплин;
- вернуть всё обратно.

### Поля класса

```cpp
void* target_;       // начало перехватываемой функции
void* hook_;         // наш обработчик
size_t patchSize_;   // сколько байт заменяем

BYTE oldBytes_[32];  // оригинальные байты
BYTE newBytes_[32];  // новые байты с переходом
void* trampoline_;   // память трамплина
DWORD oldProtect_;   // старая защита страницы
bool installed_;     // установлен ли хук
bool absoluteJump_;  // используется ли FF 25
```

Размер 32 байта выбран с запасом: реальные патчи — 6–16 байт.

### Относительный и абсолютный переход

Относительный переход:

```asm
E9 <4 байта смещения>
```

Он занимает 5 байт и умеет прыгать в пределах ±2 ГБ от следующей
инструкции. Смещение считается так:

```cpp
intptr_t delta = hook - (target + 5);
```

Если `delta` помещается в 32-битное знаковое число, используется
`E9`.

Абсолютный переход:

```asm
FF 25 00 00 00 00
<8 байт адреса>
```

Это `jmp qword ptr [rip+0]`: процессор читает 8-байтный адрес,
лежащий сразу после инструкции, и прыгает по нему. Такой переход
занимает 14 байт и работает на любом расстоянии.

### `BuildNewBytes`

```cpp
bool HookPatch::BuildNewBytes() {
    if (target_ == nullptr || hook_ == nullptr) {
        return false;
    }
    if (patchSize_ < kRelativeJumpSize || patchSize_ > sizeof(newBytes_)) {
        return false;
    }

    ZeroMemory(newBytes_, sizeof(newBytes_));

    const intptr_t delta = reinterpret_cast<BYTE*>(hook_) -
                           (reinterpret_cast<BYTE*>(target_) + kRelativeJumpSize);
    const int32_t relative = static_cast<int32_t>(delta);
    absoluteJump_ = static_cast<intptr_t>(relative) != delta;

    if (absoluteJump_) {
        if (patchSize_ < kAbsoluteJumpSize) {
            return false;
        }

        newBytes_[0] = 0xFF;
        newBytes_[1] = 0x25;
        const uintptr_t hookAddress = reinterpret_cast<uintptr_t>(hook_);
        memcpy(&newBytes_[6], &hookAddress, sizeof(hookAddress));
        memset(&newBytes_[kAbsoluteJumpSize], 0x90,
               patchSize_ - kAbsoluteJumpSize);
        return true;
    }

    newBytes_[0] = 0xE9;
    memcpy(&newBytes_[1], &relative, sizeof(relative));
    memset(&newBytes_[kRelativeJumpSize], 0x90,
           patchSize_ - kRelativeJumpSize);
    return true;
}
```

Что важно:

- `delta` — расстояние от конца 5-байтного перехода до обработчика.
- `static_cast<int32_t>(delta)` обрезает число до 32 бит. Если после
  обратного преобразования число не совпало, значит, расстояние
  слишком большое.
- В абсолютном варианте адрес записывается в `newBytes_[6]`, потому
  что первые 6 байт — это `FF 25` и нулевой `disp32`.
- Остаток патча заполняется `NOP` (`0x90`), чтобы не оставлять
  случайные байты.

### `AllocateTrampoline`

```cpp
bool HookPatch::AllocateTrampoline() {
    trampoline_ = VirtualAlloc(nullptr,
                               patchSize_ + kTrampolineTailSize,
                               MEM_COMMIT | MEM_RESERVE,
                               PAGE_EXECUTE_READWRITE);
    ...
    BYTE* trampoline = static_cast<BYTE*>(trampoline_);
    memcpy(trampoline, oldBytes_, patchSize_);

    BYTE* jumpBack = trampoline + patchSize_;
    jumpBack[0] = 0xFF;
    jumpBack[1] = 0x25;
    ZeroMemory(&jumpBack[2], 4);

    const uintptr_t returnAddress =
        reinterpret_cast<uintptr_t>(target_) + patchSize_;
    memcpy(&jumpBack[6], &returnAddress, sizeof(returnAddress));
    return true;
}
```

Трамплин выглядит так:

```text
[оригинальные N байт]
FF 25 00 00 00 00
[адрес target + N]
```

То есть сначала выполняются инструкции, которые мы забрали из
функции, а потом управление возвращается в функцию сразу после
патча.

Размер `N + 14`: `N` байт оригинала плюс 14 байт абсолютного
перехода назад.

### `Install`

```cpp
bool HookPatch::Install(void** trampolineOut) {
    if (installed_) {
        if (trampolineOut != nullptr) {
            *trampolineOut = trampoline_;
        }
        return true;
    }

    if (trampolineOut != nullptr) {
        *trampolineOut = nullptr;
    }

    if (!BuildNewBytes()) {
        return false;
    }

    memcpy(oldBytes_, target_, patchSize_);
    if (!AllocateTrampoline()) {
        return false;
    }

    if (trampolineOut != nullptr) {
        *trampolineOut = trampoline_;
    }

    if (!VirtualProtect(target_, patchSize_,
                        PAGE_EXECUTE_READWRITE, &oldProtect_)) {
        if (trampolineOut != nullptr) {
            *trampolineOut = nullptr;
        }
        FreeTrampoline();
        return false;
    }

    memcpy(target_, newBytes_, patchSize_);
    FlushInstructionCache(GetCurrentProcess(), target_, patchSize_);

    DWORD ignored = 0;
    VirtualProtect(target_, patchSize_, oldProtect_, &ignored);
    installed_ = true;
    return true;
}
```

Порядок специально такой:

1. Построить новые байты.
2. Сохранить оригинальные байты.
3. Выделить трамплин и скопировать туда оригинал.
4. Отдать адрес трамплина вызывающему коду.
5. Разрешить запись в страницу с кодом.
6. Записать патч.
7. Сбросить кэш инструкций.
8. Вернуть старую защиту страницы.

Пункт 4 важен: `g_trampoline` в DLL должен быть заполнен **до** того,
как в функцию кто-то войдёт через новый патч. Иначе обработчик
прыгнет по нулевому адресу.

### `Remove`

```cpp
bool HookPatch::Remove() {
    if (!installed_) {
        return true;
    }

    DWORD currentProtect = 0;
    if (!VirtualProtect(target_, patchSize_,
                        PAGE_EXECUTE_READWRITE, &currentProtect)) {
        return false;
    }

    memcpy(target_, oldBytes_, patchSize_);
    FlushInstructionCache(GetCurrentProcess(), target_, patchSize_);

    DWORD ignored = 0;
    VirtualProtect(target_, patchSize_, oldProtect_, &ignored);

    FreeTrampoline();
    installed_ = false;
    return true;
}
```

Сначала код снова делается доступным для записи, затем
возвращаются оригинальные байты, сбрасывается кэш инструкций,
восстанавливается защита и освобождается трамплин.

### Размеры патчей

В проекте используются такие размеры:

| Функция | N | Почему |
|---|---:|---|
| `CreateFileW` | 16 | 13 байт пролога + 3 байта следующей инструкции; позволяет и `FF 25` |
| `FindFirstFileW` | 9 | 9 байт пролога |
| `FindNextFileW` | 11 | 11 байт пролога |
| `CloseHandle` | 6 | 6 байт пролога |

Размеры зависят от версии Windows. На другой сборке пролог может
отличаться, и таблицу нужно перемерить. Нельзя брать «среднее»
значение для всех функций: можно разрезать инструкцию и уронить
процесс.

### Потокобезопасность

`Install` не приостанавливает другие потоки. Если в момент записи
патча другой поток уже выполняет первые байты функции, возможна
редкая гонка. В учебной работе целевая программа запускается
заранее и ждёт 3 секунды, поэтому на практике этого достаточно.
Для надёжного инструмента нужно приостанавливать потоки или
использовать более сложную схему.

## 8. Ассемблерный обработчик

Файл:

- [`src/hook/hook_handler.asm`](../src/hook/hook_handler.asm)

Код:

```asm
; Ассемблерный обработчик для режима -func
; Сохраняет регистры, вызывает Status(), затем прыгает в трамплин
; конкретного HookPatch (адрес лежит в g_trampoline)

OPTION CASEMAP:NONE

_TEXT SEGMENT

EXTERN Status: PROC
EXTERN g_trampoline: qword

; Вызывается вместо начала оригинальной функции
hook_handler PROC
    push rax
    push rbx
    push rcx
    push rdx
    push rsi
    push rdi
    push rbp
    push r8
    push r9
    push r10
    push r11
    push r12
    push r13
    push r14
    push r15

    sub rsp, 32         ; shadow space для Status
    call Status
    add rsp, 32

    pop r15
    pop r14
    pop r13
    pop r12
    pop r11
    pop r10
    pop r9
    pop r8
    pop rbp
    pop rdi
    pop rsi
    pop rdx
    pop rcx
    pop rbx
    pop rax

    jmp qword ptr [g_trampoline]
hook_handler ENDP

_TEXT ENDS
END
```

### Что происходит по шагам

1. **Сохранение регистров.** `push` кладёт значения 15 регистров в
   стек. Это нужно, потому что `Status()` — обычная C++-функция, она
   может испортить регистры. Оригинальная функция ожидает, что
   регистры на входе останутся такими же.
2. **`sub rsp, 32`.** По соглашению x64 перед вызовом нужно
   зарезервировать 32 байта shadow space. `Status()` не принимает
   аргументов, но место всё равно требуется.
3. **`call Status`.** Вызывается C++-функция, которая формирует
   сообщение `LOG ...` и пишет его в канал.
4. **`add rsp, 32`.** Убираем shadow space.
5. **Восстановление регистров.** `pop` в обратном порядке. Стек
   возвращается в исходное состояние.
6. **`jmp qword ptr [g_trampoline]`.** Переход на трамплин. Это
   не `call`, потому что мы не должны возвращаться в обработчик:
   после трамплина функция вернётся сразу вызывающему коду.

`g_trampoline` — глобальная переменная в DLL. Её заполняет
`HookPatch::Install` через параметр `&g_trampoline`.

### Почему `extern "C"`

В C++ имя функции может быть искажено (`mangled`). Ассемблеру нужно
простое имя `Status`. Поэтому в C++ объявление обёрнуто в
`extern "C"`:

```cpp
extern "C" void Status();
extern "C" void* g_trampoline = nullptr;
```

## 9. Режим -func

### Таблица функций

В DLL есть таблица:

```cpp
struct HookTarget {
    const char* name;
    size_t patchSize;
};

const HookTarget kTargets[] = {
    {"CreateFileW", 16},
    {"FindFirstFileW", 9},
    {"FindNextFileW", 11},
    {"CloseHandle", 6},
};
```

Она ограничивает набор функций. Это не случайно: для каждой нужен
свой безопасный размер патча. Если добавить произвольную функцию,
придётся либо измерить её пролог вручную, либо использовать
дизассемблер длины.

### Установка

```cpp
bool InstallFunctionHook(const char* name) {
    const HookTarget* info = FindTarget(name);
    if (info == nullptr) {
        return false;
    }

    HMODULE kernelbase = GetModuleHandleW(L"kernelbase.dll");
    void* target = reinterpret_cast<void*>(
        GetProcAddress(kernelbase, info->name));
    if (target == nullptr) {
        return false;
    }

    strncpy_s(g_function, sizeof(g_function), name, _TRUNCATE);
    g_functionPatch = new HookPatch(
        target,
        reinterpret_cast<void*>(&hook_handler),
        info->patchSize);

    if (!g_functionPatch->Install(&g_trampoline)) {
        delete g_functionPatch;
        g_functionPatch = nullptr;
        g_function[0] = '\0';
        return false;
    }
    return true;
}
```

Шаги:

1. Найти функцию в таблице.
2. Получить её адрес через `GetProcAddress`.
3. Запомнить имя функции в `g_function`.
4. Создать `HookPatch` с обработчиком `hook_handler`.
5. Установить хук и получить трамплин в `g_trampoline`.

### `Status`

```cpp
extern "C" void Status() {
    if (g_pipe == INVALID_HANDLE_VALUE || g_function[0] == '\0') {
        return;
    }

    SYSTEMTIME time{};
    GetLocalTime(&time);

    char message[kBufferSize];
    sprintf_s(message, "LOG %02d:%02d:%02d %s",
              time.wHour, time.wMinute, time.wSecond, g_function);

    EnterCriticalSection(&g_logLock);
    SendMessage(message);
    LeaveCriticalSection(&g_logLock);
}
```

Что важно:

- функция вызывается из ассемблерного обработчика при каждом вызове
  перехваченной функции;
- `GetLocalTime` даёт локальное время;
- `sprintf_s` формирует строку;
- `EnterCriticalSection` защищает запись в канал от нескольких
  потоков одновременно;
- `SendMessage` пишет строку в pipe.

Логирование не подавляет повторы: двадцать вызовов дадут двадцать
строк `LOG`.

### Алиасы

`monitor` умеет принимать `CreateFile`, `FindFirstFile` и
`FindNextFile`:

```cpp
std::wstring NormalizeFunction(const std::wstring& name) {
    if (_wcsicmp(name.c_str(), L"CreateFile") == 0) {
        return L"CreateFileW";
    }
    if (_wcsicmp(name.c_str(), L"FindFirstFile") == 0) {
        return L"FindFirstFileW";
    }
    if (_wcsicmp(name.c_str(), L"FindNextFile") == 0) {
        return L"FindNextFileW";
    }
    return name;
}
```

Так пользователю не нужно помнить про суффикс `W`.

## 10. Режим -hide

### Задача

Нужно, чтобы для целевого процесса файл `secret.txt`:

- не появлялся в перечислении каталога;
- не открывался через `CreateFileW`.

При этом соседние файлы должны остаться.

### Три хука

```text
FindFirstFileW  → MyFindFirstFileW
FindNextFileW   → MyFindNextFileW
CreateFileW     → MyCreateFileW
```

Порядок установки:

1. `FindNextFileW` — потому что `MyFindFirstFileW` использует
   трамплин `FindNext`.
2. `CreateFileW`.
3. `FindFirstFileW`.

Если какой-то шаг не удался, `RemoveHidePatches` снимает уже
поставленные хуки.

### Подготовка пути

`monitor` делает путь полным и проверяет существование файла:

```cpp
bool ResolveFile(const std::wstring& text, std::wstring& fullPath) {
    wchar_t buffer[MAX_PATH];
    DWORD length = GetFullPathNameW(text.c_str(), MAX_PATH,
                                    buffer, nullptr);
    if (length == 0 || length >= MAX_PATH) {
        return false;
    }
    if (GetFileAttributesW(buffer) == INVALID_FILE_ATTRIBUTES) {
        return false;
    }
    fullPath = buffer;
    return true;
}
```

Затем путь передаётся в DLL как UTF-8. DLL преобразует его обратно
в широкую строку и запоминает полный путь и имя файла:

```cpp
bool PrepareHiddenPath(const char* utf8Path) {
    if (!ConvertUtf8ToWide(utf8Path, g_hiddenPath, MAX_PATH)) {
        return false;
    }

    const wchar_t* name = wcsrchr(g_hiddenPath, L'\\');
    name = (name != nullptr) ? name + 1 : g_hiddenPath;
    wcscpy_s(g_hiddenName, MAX_PATH, name);
    return true;
}
```

### Сравнение пути

```cpp
bool IsHiddenPath(const wchar_t* path) {
    if (path == nullptr || g_hiddenPath[0] == L'\0') {
        return false;
    }
    if (_wcsicmp(path, g_hiddenPath) == 0) {
        return true;
    }

    wchar_t fullPath[MAX_PATH];
    DWORD length = GetFullPathNameW(path, MAX_PATH, fullPath, nullptr);
    return length > 0 && length < MAX_PATH &&
           _wcsicmp(fullPath, g_hiddenPath) == 0;
}
```

Сравнение регистронезависимое: `C:\Temp\Secret.txt` и
`c:\temp\secret.txt` считаются одним файлом.

### `MyCreateFileW`

```cpp
HANDLE WINAPI MyCreateFileW(LPCWSTR fileName, DWORD desiredAccess,
                            DWORD shareMode,
                            LPSECURITY_ATTRIBUTES security,
                            DWORD creationDisposition, DWORD flags,
                            HANDLE templateFile) {
    if (IsHiddenPath(fileName)) {
        SetLastError(ERROR_FILE_NOT_FOUND);
        return INVALID_HANDLE_VALUE;
    }

    auto real = reinterpret_cast<CreateFileW_t>(g_realCreateFile);
    return real(fileName, desiredAccess, shareMode, security,
                creationDisposition, flags, templateFile);
}
```

Если файл скрытый, вызывающий получает `INVALID_HANDLE_VALUE` и
ошибку `ERROR_FILE_NOT_FOUND` (код 2). Оригинальная функция не
вызывается.

### `MyFindNextFileW`

```cpp
BOOL WINAPI MyFindNextFileW(HANDLE handle, LPWIN32_FIND_DATAW data) {
    auto real = reinterpret_cast<FindNextFileW_t>(g_realFindNext);
    for (;;) {
        if (!real(handle, data)) {
            return FALSE;
        }
        if (!IsHiddenName(data->cFileName)) {
            return TRUE;
        }
    }
}
```

Функция вызывает оригинальный `FindNextFileW` до тех пор, пока не
найдёт не скрытое имя. Если файлы закончились, возвращает `FALSE`.

### `MyFindFirstFileW`

```cpp
HANDLE WINAPI MyFindFirstFileW(LPCWSTR fileName,
                               LPWIN32_FIND_DATAW data) {
    if (IsHiddenPath(fileName)) {
        SetLastError(ERROR_FILE_NOT_FOUND);
        return INVALID_HANDLE_VALUE;
    }

    auto real = reinterpret_cast<FindFirstFileW_t>(g_realFindFirst);
    HANDLE handle = real(fileName, data);
    if (handle == INVALID_HANDLE_VALUE) {
        return handle;
    }

    // Если первый результат — скрытый файл, листаем дальше
    while (IsHiddenName(data->cFileName)) {
        auto realNext = reinterpret_cast<FindNextFileW_t>(g_realFindNext);
        if (!realNext(handle, data)) {
            DWORD error = GetLastError();
            FindClose(handle);
            SetLastError(error == ERROR_NO_MORE_FILES
                             ? ERROR_FILE_NOT_FOUND
                             : error);
            return INVALID_HANDLE_VALUE;
        }
    }
    return handle;
}
```

Если первый результат — скрытый файл, обёртка листает дальше. Если
больше ничего нет, возвращает «файл не найден», а не «больше нет
файлов».

### Пример

Victim перечисляет текущий каталог:

```cpp
const HANDLE find = FindFirstFileW(L"*", &data);
if (find != INVALID_HANDLE_VALUE) {
    do {
        ++entries;
        if (_wcsicmp(data.cFileName, kTargetFile) == 0) {
            listed = true;
        }
        wprintf(L" %ls", data.cFileName);
    } while (FindNextFileW(find, &data));
    FindClose(find);
}
```

При включённом `-hide` вывод:

```text
[00] . .. aaa.txt zzz.txt
[00] entries=4 secret=no open=fail err=2
```

`secret.txt` не появляется, а `CreateFileW` возвращает ошибку 2.

### Почему `FindFirst`/`FindNext` требуют близкой DLL

Для этих функций размер патча 9 и 11 байт. Абсолютный переход
`FF 25` требует 14 байт и не помещается. Значит, используется
относительный `E9`, который достаёт только на ±2 ГБ. `hook.dll`
должна быть загружена в пределах этого расстояния от `kernelbase`.
На практике DLL в каталоге проекта обычно рядом, но это стоит
помнить.

## 11. monitor.exe изнутри

Файл:

- [`src/monitor/monitor.cpp`](../src/monitor/monitor.cpp)

### Стандартный `main` и широкие аргументы

В проекте используется обычный `main`, но аргументы берутся через
`CommandLineToArgvW`:

```cpp
struct CommandLine {
    int argc = 0;
    wchar_t** argv = CommandLineToArgvW(GetCommandLineW(), &argc);

    CommandLine() = default;

    ~CommandLine() {
        if (argv != nullptr) {
            LocalFree(argv);
        }
    }

    CommandLine(const CommandLine&) = delete;
    CommandLine& operator=(const CommandLine&) = delete;
};
```

Почему так:

- `main(int argc, char** argv)` даёт узкие строки;
- пути и имена процессов в Windows лучше хранить в `wchar_t`;
- `CommandLineToArgvW` сразу разбирает `GetCommandLineW` в широкий
  массив;
- деструктор освобождает память через `LocalFree` при любом выходе.

Для `CommandLineToArgvW` подключён `shell32.lib`.

### `main`

```cpp
int main() {

        return 1;

    wchar_t** argv = commandLine.argv;

    Options options;
    DWORD pid = 0;

    if (argc < 3 || !ParseOptions(argc, argv, options, pid)) {
        wprintf(L"Usage:\n");
        ...
        return 1;
    }

        while ((pid = FindProcessId(options.processName)) == 0) {
            Sleep(500);
        }
    }

    std::wstring pluginPath;
    if (!GetPluginPath(pluginPath)) {
        ...
    }

    if (!InjectDll(pid, pluginPath)) {
        ...
    }

    if (!RunProtocol(pid, options)) {
        ...
    }

    wprintf(L"[monitor] done\n");
    return 0;
}
```

Кратко:

1. Получить аргументы.
2. Разобрать их.
3. Если указано имя — дождаться процесса.
4. Найти `hook.dll`.
5. Загрузить её.
6. Обменяться командами.
7. Завершиться с кодом 0.

### `ParseOptions`

```cpp
bool ParseOptions(int argc, wchar_t** argv, Options& options,
                  DWORD& pid) {
    bool havePid = false;
    bool haveName = false;
    bool haveFunc = false;
    bool haveHide = false;

    for (int i = 1; i < argc; ++i) {
        if (wcscmp(argv[i], L"-pid") == 0 && i + 1 < argc) {
            if (!ParsePid(argv[++i], options.pid)) {
                return false;
            }
            havePid = true;
        } else if (wcscmp(argv[i], L"-name") == 0 && i + 1 < argc) {
            options.processName = argv[++i];
            options.useName = true;
            haveName = true;
        } else if (wcscmp(argv[i], L"-func") == 0 && i + 1 < argc) {
            options.functionName =
                WideToUtf8(NormalizeFunction(argv[++i]));
            options.hide = false;
            haveFunc = true;
        } else if (wcscmp(argv[i], L"-hide") == 0 && i + 1 < argc) {
            if (!ResolveFile(argv[++i], options.filePath)) {
                wprintf(L"[-] File does not exist: %ls\n", argv[i]);
                return false;
            }
            options.hide = true;
            haveHide = true;
        } else {
            return false;
        }
    }

    if (havePid == haveName) {
        return false;
    }
    if (haveFunc == haveHide) {
        return false;
    }
    if (options.functionName.size() + 1 > kBufferSize) {
        return false;
    }

    pid = options.pid;
    return true;
}
```

Проверки:

- `-pid` и `-name` взаимоисключающие;
- `-func` и `-hide` взаимоисключающие;
- у параметра должно быть значение (`i + 1 < argc`);
- PID должен быть числом;
- файл для `-hide` должен существовать;
- имя функции должно помещаться в буфер канала.

`argv[0]` — имя программы, поэтому цикл начинается с `i = 1`.

### Поиск процесса

```cpp

    HANDLE snapshot = CreateToolhelp32Snapshot(TH32CS_SNAPPROCESS, 0);
    ...
    PROCESSENTRY32W entry{};
    entry.dwSize = sizeof(entry);

        do {
            if (_wcsicmp(entry.szExeFile, processName.c_str()) == 0) {
                return entry.th32ProcessID;
            }
        } while (Process32NextW(snapshot, &entry));
    }
    ...
}
```

Toolhelp32 — стандартный способ перечислить процессы. Имя
сравнивается без учёта регистра. Если процесса нет, возвращается 0,
и `main` ждёт.

### Поиск `hook.dll`

```cpp
bool GetPluginPath(std::wstring& path) {
    wchar_t exePath[MAX_PATH];
    DWORD length = GetModuleFileNameW(nullptr, exePath, MAX_PATH);
    ...
    wchar_t* slash = wcsrchr(exePath, L'\\');
    *(slash + 1) = L'\0';

    path = std::wstring(exePath) + L"hook.dll";
    return GetFileAttributesW(path.c_str()) != INVALID_FILE_ATTRIBUTES;
}
```

DLL ищется рядом с `monitor.exe`. Если её нет — ошибка до инъекции.

### Канал и протокол

`RunProtocol`:

1. Создаёт `CreateNamedPipeW`.
2. Ждёт `ConnectNamedPipe`.
3. Читает `HELLO <pid>`.
4. Проверяет PID.
5. Отправляет `-func ...` или `-hide ...`.
6. Читает `OK`/`ERROR`; в режиме `-func` продолжает читать `LOG`.
7. Закрывает канал.

Важная деталь: `monitor` загружает DLL **до** создания канала. DLL
делает несколько попыток подключения, поэтому успевает.

## 12. victim.exe

Файл:

- [`src/victim/victim.cpp`](../src/victim/victim.cpp)

Это не часть библиотеки, а тестовая цель. Каталог не передаётся
аргументом: `victim` работает в текущем каталоге процесса, поэтому
запускать его нужно из `src\victim\data`, где лежат `aaa.txt`,
`secret.txt` и `zzz.txt`.

```cpp
int main() {
    // Абсолютный путь печатаем, чтобы его же можно было передать в -hide
    wchar_t targetPath[MAX_PATH] = {};
    GetFullPathNameW(kTargetFile, MAX_PATH, targetPath, nullptr);

    wprintf(L"[victim] pid=%lu target=%ls\n", GetCurrentProcessId(), targetPath);
    wprintf(L"[victim] waiting %lu ms for the monitor\n", kStartDelayMs);
    fflush(stdout);
    Sleep(kStartDelayMs);

    for (int i = 0; i < kIterations; ++i) {
        WIN32_FIND_DATAW data{};
        int entries = 0;
        bool listed = false;

        wprintf(L"[%02d]", i);
        const HANDLE find = FindFirstFileW(L"*", &data);
        if (find != INVALID_HANDLE_VALUE) {
            do {
                ++entries;
                if (_wcsicmp(data.cFileName, kTargetFile) == 0) {
                    listed = true;
                }
                wprintf(L" %ls", data.cFileName);
            } while (FindNextFileW(find, &data));
            FindClose(find);
        }

        const HANDLE file = CreateFileW(kTargetFile, GENERIC_READ, FILE_SHARE_READ,
                                        nullptr, OPEN_EXISTING,
                                        FILE_ATTRIBUTE_NORMAL, nullptr);
        if (file == INVALID_HANDLE_VALUE) {
            wprintf(L"\n[%02d] entries=%d secret=%ls open=fail err=%lu\n",
                    i, entries, listed ? L"yes" : L"no", GetLastError());
        } else {
            CloseHandle(file);
            wprintf(L"\n[%02d] entries=%d secret=%ls open=ok\n",
                    i, entries, listed ? L"yes" : L"no");
        }

        fflush(stdout);
        Sleep(kStepDelayMs);
    }
    return 0;
}
```

Константы в начале файла: `kIterations`, `kStartDelayMs`,
`kStepDelayMs`, `kTargetFile`. Маска `L"*"` и имя `L"secret.txt"` —
относительные, их разворачивает операционная система от текущего
каталога. Поэтому в коде нет ни `std::wstring`, ни склейки путей.

Почему 20 раз и 500 мс:

- 20 вызовов достаточно, чтобы увидеть, что лог пишется на каждый
  вызов;
- пауза 500 мс делает вывод читаемым;
- 3 секунды в начале дают monitor время на инъекцию и установку
  хука.

- `hook` использует MASM (`masm.props` / `masm.targets`);
- `monitor` и `victim` добавляют `shell32.lib` для
  `CommandLineToArgvW`.

Выходные файлы:

```text
bin/x64/Debug/
bin/x64/Release/
```

`hook.dll` должна лежать рядом с `monitor.exe`: `GetPluginPath`
ищет её именно там.

---

## 14. Проверка

### Мониторинг

```powershell
$victim = Start-Process bin\x64\Debug\victim.exe -PassThru `
    -WorkingDirectory src\victim\data
Start-Sleep -Milliseconds 400
bin\x64\Debug\monitor.exe -pid $victim.Id -func CreateFileW
```

Ожидаемо:

```text
[monitor] target pid=...
[monitor] dll=...\hook.dll
[monitor] mode=func
[monitor] LoadLibraryW -> 0x... (loaded)
[monitor] pipe connected
[monitor] <- HELLO ...
[monitor] <- OK hooked
[monitor] LOG ...
...
[monitor] target disconnected
[monitor] done
```

Проверка: число `LOG` равно числу строк `open=ok` в выводе victim. В
текущей версии — 20 и 20.

### Скрытие

```powershell
$victim = Start-Process bin\x64\Debug\victim.exe -PassThru `
    -WorkingDirectory src\victim\data
Start-Sleep -Milliseconds 400
bin\x64\Debug\monitor.exe -pid $victim.Id -hide `
    (Resolve-Path src\victim\data\secret.txt).Path
Start-Sleep -Seconds 4
Stop-Process -Id $victim.Id
```

Ожидаемо:

```text
[00] . .. aaa.txt zzz.txt
[00] entries=4 secret=no open=fail err=2
```

### По имени и алиасу

```powershell
bin\x64\Debug\monitor.exe -name victim.exe -func CreateFile
```

Должно быть 20 логов: `CreateFile` приводится к `CreateFileW`.

### Ошибки

```text
monitor.exe
    → usage, код 1

monitor.exe -pid 1 -hide C:\no_such_file.txt
    → файл не существует, код 1

monitor.exe -pid 1 -func MessageBoxW
    → ERROR unsupported function
```

## 15. Диагностика

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| `hook.dll was not found` | DLL не собрана или лежит не рядом с monitor | собрать `hook`, проверить `bin` |
| `OpenProcess failed, error=5` | нет прав | запустить от того же пользователя/уровня прав |
| `LoadLibraryW -> 0 (failed)` | DLL не загрузилась | проверить зависимости, разрядность, путь |
| `HELLO was not received` | DLL не подключилась к каналу | проверить, что загружена нужная DLL; повторить |
| `ERROR unsupported function` | функции нет в таблице | использовать `CreateFileW`, `FindFirstFileW`, `FindNextFileW` или `CloseHandle` |
| `ERROR hide failed` | не ставится один из хуков | проверить размер патча, адрес функции, расстояние до DLL |
| Процесс упал после установки хука | неверный размер патча или разрезана инструкция | перемерить пролог, проверить N |
| `CreateFileW` не скрывается | путь не совпал | проверить полный путь и регистр |
| `FindFirstFileW` не скрывает | не тот путь/маска | проверить, что файл действительно попадает в маску |
| Канал занят | уже запущен другой monitor | закрыть старый процесс |
| Ничего не работает в Release | нет debug CRT | собрать Release или установить CRT |

## 16. Ограничения

1. **Только измеренные функции.** `-func` работает с таблицей из
   четырёх функций. Произвольная функция потребует дизассемблера
   длины.
2. **Относительный патч для маленьких прологов.** `FindFirstFileW`
   и `FindNextFileW` не вмещают `FF 25`, поэтому DLL должна быть в
   пределах ±2 ГБ от `kernelbase`.
3. **Обычные пути.** Скрытие не покрывает `\\?\`, короткие 8.3-имена
   и некоторые нестандартные формы.
4. **Один канал.** Имя `lab1_monitor` фиксировано, одновременно
   может работать один экземпляр.
5. **x64.** 32-битные процессы не поддерживаются.
6. **Права.** monitor и target должны быть доступны одному
   пользователю; защищённые процессы открыть не получится.
7. **Гонка при установке.** Другие потоки не приостанавливаются.
   В учебной работе это скрыто задержкой victim.
8. **Нет снятия хуков при выгрузке DLL.** В `DllMain` нет обработки
   `DLL_PROCESS_DETACH`; для демонстрации это не нужно.
9. **Debug CRT.** Debug-сборка DLL зависит от отладочной CRT; на
   чистой машине лучше Release.

## 17. Как расширять

### Добавить новую функцию в `-func`

1. Измерить её пролог в отладчике.
2. Добавить запись в `kTargets`.
3. Проверить, что размер патча достаточен для `E9`/`FF 25`.
4. Пересобрать DLL.

### Поддержать произвольные функции

Нужен дизассемблер длины (Zydis, Capstone, BeaEngine). Он читает
инструкции с начала функции, пока не наберётся минимум 5 или 14
байт, и возвращает границу последней целой инструкции. Затем это
значение передаётся в `HookPatch`.

Псевдокод:

```cpp
size_t length = 0;
while (length < 14) {
    size_t instruction = disassemble_one(target + length);
    if (instruction == 0) {
        return false;
    }
    length += instruction;
}
```

### Приостановить потоки

Для надёжной установки хука в многопоточном процессе можно
использовать `Thread32First`/`Thread32Next` и `SuspendThread`, затем
`ResumeThread`. Это сложнее и требует аккуратности.

### Снимать хуки при выгрузке

В `DllMain` при `DLL_PROCESS_DETACH` можно вызвать
`RemoveHidePatches`/`RemovePatch`, но нельзя делать сложные
операции под loader lock. Для учебной работы проще не выгружать
DLL до завершения процесса.

### Сделать канал уникальным

Добавить PID в имя канала:

```cpp
std::wstring pipeName = L"\\\\.\\pipe\\lab1_monitor_" +
                        std::to_wstring(GetCurrentProcessId());
```

Тогда можно запускать несколько экземпляров.

## 18. Глоссарий

| Термин | Значение |
|---|---|
| **PID** | идентификатор процесса |
| **HMODULE** | база загруженного модуля |
| **RVA** | смещение от базы модуля |
| **Пролог** | первые инструкции функции |
| **Inline-хук** | замена начала функции переходом |
| **Трамплин** | копия оригинальных инструкций + переход назад |
| **`E9`** | относительный переход x86/x64, 5 байт |
| **`FF 25`** | абсолютный переход через указатель, 14 байт |
| **Shadow space** | 32 байта стека перед вызовом x64-функции |
| **Named pipe** | именованный канал Windows |
| **Message mode** | режим канала, сохраняющий границы сообщений |
| **RAII** | освобождение ресурса в деструкторе объекта |
| **CRT** | C runtime, стандартная библиотека C |
