Инструкция по рисункам для отчёта по лабораторной работе № 1

Общие правила

1. Команды выполняются из каталога проекта:
   cd C:\Users\winuser\Documents\trspo_labs\lab1

2. Сборка перед скриншотами: Visual Studio 2026, конфигурация Debug | x64, собрать решение. Готовые файлы лежат в bin\x64\Debug: monitor.exe, hook.dll, victim.exe. hook.dll должна лежать рядом с monitor.exe.

3. Терминал: ширина 120–140 символов, шрифт 12–14 пт, одна тема на все рисунки. В кадре видны команда и её вывод. Пустые поля и лишние окна обрезать.

4. Если вывод длинный, оставить начало и конец, но так, чтобы было понятно, какая команда выполнялась. Нельзя обрезать строки с ошибками, HELLO, OK, ERROR и кодом завершения.

5. В ОТЧЁТ.md места вставки отмечены строками МЕСТО ДЛЯ РИСУНКА N. После вставки изображения эти строки удалить, подпись рисунка оставить.

6. В ОТЧЁТ.md две таблицы записаны строками с разделителем |. В Google Docs их оформить как таблицы.

7. PID, адрес LoadLibraryW и время в строках LOG на новом запуске будут другими. В отчёте записан один конкретный прогон: 20 строк LOG, у victim без скрытия count=5 и OPEN OK, со скрытием count=4, secret_listed=0 и OPEN FAILED err=2.

8. Рисунки 2 и 3 уже сняты. Это файлы docs\history\images\stage1-breakpoint-source.png и docs\history\images\stage1-createfilew-disassembly.png. На них измерительная программа с циклом CreateFileW. Байты в дизассемблере совпадают с таблицей в отчёте. Переснимать не нужно, если кадр читается.

РИСУНОК 1 — Структура каталогов проекта

Где вставить: раздел 3, рисунок 1. В ОТЧЁТ.md: МЕСТО ДЛЯ РИСУНКА 1.

Команда:
tree /A /F src

Что должно быть видно:
- каталоги src\hook, src\monitor, src\victim;
- в hook файлы dllmain.cpp, HookPatch.cpp, HookPatch.h, hook_handler.asm;
- в monitor файл monitor.cpp;
- в victim файл victim.cpp и каталог data с aaa.txt, secret.txt, zzz.txt.

Как оформить:
Скриншот обрезать по границам вывода tree. Строку с командой оставить в кадре. Каталоги bin и obj в этот рисунок не входят: это результаты сборки.

РИСУНОК 2 — Остановка на вызове CreateFileW

Где вставить: раздел 3, этап 1, рисунок 2. В ОТЧЁТ.md: МЕСТО ДЛЯ РИСУНКА 2.

Что вставить:
Готовый файл docs\history\images\stage1-breakpoint-source.png.

Что должно быть видно:
- breakpoint на строке вызова CreateFileW;
- в стеке вызовов main тестовой программы;
- конфигурация Debug | x64.

Как оформить:
Вставить изображение как есть. Ширина в документе около 14–16 см, чтобы было читаемо имя функции. Это не скриншот терминала.

РИСУНОК 3 — Дизассемблер входа CreateFileW

Где вставить: раздел 3, этап 1, рисунок 3. В ОТЧЁТ.md: МЕСТО ДЛЯ РИСУНКА 3.

Что вставить:
Готовый файл docs\history\images\stage1-createfilew-disassembly.png.

Что должно быть видно:
- адрес входа и инструкции push rbx, sub rsp,50h, mov eax,dword ptr [rsp+88h];
- в стеке вызовов кадр KernelBase.dll, а под ним тестовая программа;

Как оформить:
Вставить сразу после рисунка 2. Если текст в кадре мелкий, ширину увеличить, но не обрезать первые три инструкции пролога.

Если понадобится переснять рисунки 2 и 3: открыть src\victim\victim.cpp, поставить breakpoint на CreateFileW, снять галочку Enable Just My Code, запустить victim.exe с рабочим каталогом src\victim, на остановке нажать Step Into. Для рисунка 2 снять исходник и Call Stack до шага внутрь. Для рисунка 3 снять Disassembly и Call Stack уже внутри kernelbase. Абсолютный адрес будет другим, инструкции пролога те же.

РИСУНОК 4 — Режим -func

Где вставить: раздел 3, прогон, рисунок 4. В ОТЧЁТ.md: МЕСТО ДЛЯ РИСУНКА 4.

Окно 1, рабочий каталог src\victim:
..\..\bin\x64\Debug\victim.exe

Дождаться строки [victim] pid=... и сразу, в пределах трёх секунд, в окне 2:

bin\x64\Debug\monitor.exe -pid <PID> -func CreateFileW

Что должно быть видно:
- у monitor: LoadLibraryW с ненулевым кодом и словом loaded, HELLO с тем же PID, OK hooked;
- строки LOG ... CreateFileW, в конце target disconnected и done;
- у victim: secret.txt в списке, count=5, secret_listed=1, OPEN OK.

Как оформить:
Вывод victim длинный, у него 20 одинаковых итераций. Показать первую итерацию целиком и последнюю строку OPEN OK. У monitor показать начало до первого LOG и конец с target disconnected. Можно склеить два окна в один рисунок. Ошибок быть не должно.

Вариант по имени, если нужен второй кадр к этому же рисунку:
bin\x64\Debug\monitor.exe -name victim.exe -func CreateFile

В журнале имя всё равно CreateFileW.

РИСУНОК 5 — Режим -hide

Где вставить: раздел 3, прогон, рисунок 5. В ОТЧЁТ.md: МЕСТО ДЛЯ РИСУНКА 5.

Этот рисунок делать после рисунка 4: прятать файл, пока снимается журнал открытий, не нужно.

Окно 1, рабочий каталог src\victim:
..\..\bin\x64\Debug\victim.exe

Окно 2, сразу после строки с PID:
bin\x64\Debug\monitor.exe -pid <PID> -hide C:\Users\winuser\Documents\trspo_labs\lab1\src\victim\data\secret.txt

Путь можно получить так:
monitor.exe -pid <PID> -hide (Resolve-Path src\victim\data\secret.txt).Path

Что должно быть видно:
- у monitor: HELLO, OK hidden, done. Строк LOG нет: после подтверждения монитор выходит;
- у victim после первой итерации: в списке есть точка, две точки, aaa.txt и zzz.txt;
- строки secret.txt в списке нет;
- count=4, secret_listed=0, OPEN FAILED err=2.

Как оформить:
Монитор завершается за секунду, victim печатает первую итерацию примерно через 3 секунды после старта. Сначала дождаться OK hidden, затем дождаться у victim блока [00]. В рисунок входят оба окна. Если снять victim слишком рано, в кадре будет только строка pid, без перечисления.

ДОПОЛНИТЕЛЬНО — неподдерживаемая функция

Отдельный номер рисунку не нужен. Если хочется подтвердить абзац про MessageBoxW:

bin\x64\Debug\monitor.exe -pid <PID> -func MessageBoxW

В кадре должны быть ERROR unsupported function и строка Protocol failed. victim при этом не закрывать из монитора: процесс остаётся жив, его можно завершить вручную после скриншота.

ПОРЯДОК РАБОТЫ

1. Убедиться, что Debug | x64 собран и в bin\x64\Debug лежат monitor.exe, hook.dll и victim.exe.
2. Снять рисунок 1 командой tree.
3. Вставить готовые рисунки 2 и 3 из docs\history\images.
4. Снять рисунок 4, режим -func.
5. Снять рисунок 5, режим -hide. Victim для этого запуска заново.
6. Вставить рисунки в ОТЧЁТ.md на места МЕСТО ДЛЯ РИСУНКА N.
7. Удалить строки МЕСТО ДЛЯ РИСУНКА N, подписи рисунков оставить.
8. Оформить две таблицы из ОТЧЁТ.md как таблицы Google Docs.
9. Проверить порядок: 1 — структура, 2 — breakpoint, 3 — дизассемблер, 4 — режим -func, 5 — режим -hide.
