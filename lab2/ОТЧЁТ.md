# Лабораторная работа №2

Компилятор, компоновщик и динамические библиотеки.

## 1. Цель

Изучить этапы сборки программы при статической и динамической компоновке и автоматизировать сборку через `make`.

## 2. Задачи

Сделано:

1. Программа на C рисует строку из TTF в PNG через zlib 1.2.11, libpng 1.6.37 и FreeType 2.10.0.
2. Корневой `Makefile` собирает три версии: `static`, `dynamic`, `blob`.
3. Дополнительное задание 6.2: у каждой библиотеки свой `Makefile`, он собирает и `.a`, и `.so` без `./configure`.

Задание 6.1 (загрузчик ELF под Windows) не выполнялось.

## 3. Ход работы

Каталог `lab2/`:

```
Makefile          цели all, static, dynamic, blob, clean
build/            app-static, app-dynamic, app-blob, elfloader, библиотеки
app/              main.c, funcs.c, funcs.h, обёртки libc для blob
zlib/ libpng/ freetype/
elfloader/        загрузчик blob с диска
font.ttf
```

Аргументы у всех версий одни: файл шрифта, имя PNG, текст. При другом числе аргументов, отсутствующем шрифте или недоступной библиотеке программа пишет сообщение и завершается с кодом 0.

На экран печатаются две величины. `load` — время до начала рисования: у dynamic это `dlopen` и `dlsym`, у static и blob библиотеки уже в образе, поэтому значение около нуля. `total` — время от входа в программу до выхода. Строка `zlib 1.2.11` показывает, что zlib вызвана явно, а не только изнутри libpng.

### static

`app-static` линкуется с `libfreetype.a`, `libpng.a` и `libz.a`. libc остаётся динамической: задание требует статическую компоновку трёх библиотек, а не всего glibc.

`ldd build/app-static` показывает `libc` и `libm` и не показывает libpng, libz, libfreetype.

### dynamic

`app-dynamic` линкуется только с `-ldl`. В начале `main` библиотеки открываются в порядке `libz.so.1`, `libpng.so`, `libfreetype.so` из каталога самого бинарника (`/proc/self/exe`), флаг `RTLD_NOW`. Адреса `FT_*`, `png_*` и `zlibVersion` берутся через `dlsym`. В этой сборке `#define` в `app/dynload.h` подменяет эти имена на указатели, поэтому `funcs.c` в обоих режимах выглядит одинаково. `libpng.so` зависит от `libz.so.1` (это видно в `readelf -d`) и ищет её рядом с собой через `RPATH=$ORIGIN`.

`ldd build/app-dynamic` показывает только libc. На прогоне `load` заметно больше нуля (порядка 0,5 мс), `total` включает и загрузку, и рисование.

### blob

`app-blob` — PIE ELF (`ET_DYN`), точка входа `blob_entry` задаётся линкером (`-Wl,-e,blob_entry`), а не поиском символа. Сборка: `-nostdlib -fPIE -pie -fno-builtin`. Три библиотеки вшиты статически. Вызовы libc (`fopen`, `fread`, `fwrite`, `malloc`, `setjmp` и остальные, которые реально тянут объектные файлы) — это функции внутри blob. Они сразу передают вызов в таблицу, которую загрузчик положил в аргумент:

```c
struct blob_params {
    const char *font_path;
    const char *png_path;
    const char *text;
    struct host_api api;
};
```

`setjmp` сделан хвостовым переходом на `_setjmp` загрузчика, иначе `longjmp` из libpng вернулся бы в обёртку, а не в код записи PNG.

`readelf -d build/app-blob` не содержит `DT_NEEDED`: таблицы импорта нет. `blob_entry` в динамической таблице символов не экспортируется (`nm` показывает её как локальную, адрес совпадает с `e_entry`).

`elfloader` читает файл, отображает сегменты `PT_LOAD`, применяет только `R_X86_64_RELATIVE` и вызывает `e_entry` с заполненной структурой. Запуск:

```
./build/elfloader build/app-blob font.ttf out.png "TRSPO"
```

### Сборка

```
make static     # три .a и build/app-static
make dynamic    # три .so и build/app-dynamic
make blob       # .a, build/app-blob и build/elfloader
make all        # удаляет три бинарника и собирает их заново
make clean      # удаляет build/ и объектные файлы
```

Инкрементность проверена. `touch app/funcs.c && make static` перекомпилировал только `funcs.c` и заново слинковал `app-static`. `touch zlib/adler32.c && make static` пересобрал один объектник zlib, `libz.a` и заново слинковал приложение. Повторный `make static` без правок ничего не компилирует.

Свои Makefile библиотек (задание 6.2):

- zlib: одиннадцать файлов ядра, без gzip-обёртки;
- libpng: штатный набор `png*.c` и готовый `scripts/pnglibconf.h.prebuilt`;
- FreeType: только TrueType (`ftsystem`, `ftbase`, `ftinit`, `sfnt`, `truetype`, `psnames`, `smooth`). Список модулей — `freetype/custom/ftmodule.h`. Поддержка gzip/LZW внутри FreeType выключена, чтобы не тащить вторую копию zlib.

Правила вида `object_files/%.o: %.c`. Рецепт `init`, который компилирует всё подряд, не используется.

### Прогон

Одна и та же строка `TRSPO` и `font.ttf` дали три PNG 202×106. После распаковки IDAT число тёмных пикселей совпало: 11304 во всех трёх файлах.

Пример вывода:

```
load: 0.000000 s
zlib 1.2.11
total: 0.002891 s
```

У dynamic `load` был около 0.0005 s. Недостающие аргументы и удалённый `libz.so.1` завершаются с кодом 0, без падения.

## 4. Выводы

До входа в `main` в образе static уже лежат три библиотеки, поэтому отдельное время загрузки почти нулевое. В dynamic процесс стартует без них: `dlopen` в начале `main` и есть загрузка, её время видно отдельно от рисования. Blob не просит динамический линкер подгрузить libc или библиотеки: код библиотек внутри файла, а чужие функции приходят таблицей указателей от загрузчика. Поэтому в динамической секции нет `DT_NEEDED`.
