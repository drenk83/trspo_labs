Инструкция по рисункам для отчёта по лабораторной работе № 2

Общие правила

1. Все команды выполняются из каталога проекта:
   cd ~/Projects/gitrepo/trspo_labs/lab2

2. Перед скриншотами сделать финальную сборку:
   make clean
   make all

3. Терминал: ширина 120–140 символов, шрифт 12–14 пт, одна тема оформления на все рисунки. В кадре должны быть видны команда и её вывод. Пустые поля и лишние окна обрезать.

4. Если вывод длинный, показывать только нужную часть через head или tail, но так, чтобы было понятно, какая команда выполнялась. Нельзя обрезать строки с ошибками или кодами возврата.

5. В report.md места вставки отмечены строками МЕСТО ДЛЯ РИСУНКА N. После вставки изображения эти строки нужно удалить, а подпись рисунка оставить.

6. В report.md таблицы записаны простыми строками с разделителем |. В Google Docs их нужно оформить как таблицы: выделить строки и вставить таблицу, либо перенести данные вручную.

7. Значения времени в скриншотах могут отличаться от report.md: в отчёте указаны диапазоны после прогрева. Первый запуск dynamic после сборки может быть медленнее из-за холодного кеша.

8. Рисунок 2 — это не скриншот терминала, а сам файл out.png, полученный программой. Его нужно вставить в документ как изображение.

РИСУНОК 1 — Структура каталогов проекта

Где вставить: раздел 3.1, рисунок 1. В report.md: МЕСТО ДЛЯ РИСУНКА 1.

Команда:
tree -L 2 -I 'object_files|objs' .

Что должно быть видно:
- каталоги app, elfloader, zlib, libpng, freetype, build;
- файлы Makefile, font.ttf;
- исходные файлы внутри app и elfloader;
- каталог elfloader/elfload с исходниками библиотеки.

Как оформить:
Скриншот можно обрезать по границам вывода tree. Строку с командой лучше оставить в кадре. Если дерево получилось слишком длинным из-за подкаталогов библиотек, можно показать только верхний уровень и содержимое app/elfloader: tree -L 1 . и tree -L 2 app elfloader.

РИСУНОК 2 — Результат работы программы

Где вставить: раздел 3.2, рисунок 2. В report.md: МЕСТО ДЛЯ РИСУНКА 2.

Команда:
./build/app-static font.ttf out.png TRSPO

Что вставить:
Не скриншот терминала, а сам файл out.png. Его можно открыть в просмотрщике изображений и убедиться, что на белом фоне написан текст TRSPO. В Google Docs вставить как изображение, ширину около 8–10 см.

РИСУНОК 3 — Проверка зависимостей статической и динамической версий

Где вставить: разделы 3.3–3.4, рисунок 3. В report.md: МЕСТО ДЛЯ РИСУНКА 3.

Команды:
ldd build/app-static
ldd build/app-dynamic
readelf -d build/libpng.so | grep NEEDED
readelf -d build/libfreetype.so | grep NEEDED

Что должно быть видно:
- у app-static есть libm и libc, но нет libpng, libz, libfreetype;
- у app-dynamic есть только libc (и linux-vdso), без трёх библиотек;
- libpng.so и libfreetype.so содержат NEEDED libz.so.1.

Как оформить:
Можно сделать один длинный скриншот или два: первый с ldd, второй с readelf. Вставь оба под рисунок 3 или сделай коллаж. Главное, чтобы были видны и ldd, и NEEDED.

РИСУНОК 4 — Проверка заголовка и динамической секции blob-файла

Где вставить: раздел 3.5, рисунок 4. В report.md: МЕСТО ДЛЯ РИСУНКА 4.

Команды:
file build/app-blob
readelf -h build/app-blob | head -20
readelf -d build/app-blob

Что должно быть видно:
- file показывает ELF 64-bit, static-pie;
- readelf -h показывает Type DYN и Entry point 0x8040;
- readelf -d не содержит NEEDED;
- в динамической секции видно RELACOUNT 1308.

Как оформить:
Первый из двух скриншотов для проверки blob. Подпись в отчёте: «Рисунок 4 — Проверка заголовка и динамической секции blob-файла». Вставь подряд с рисунком 5.

РИСУНОК 5 — Проверка релокаций, символов и сегментов blob-файла

Где вставить: раздел 3.5, рисунок 5. В report.md: МЕСТО ДЛЯ РИСУНКА 5.

Команды:
readelf -rW build/app-blob | awk '/R_X86_64/{print $3}' | sort | uniq -c
readelf --dyn-syms build/app-blob
readelf -sW build/app-blob | grep blob_entry
readelf -lW build/app-blob | grep -E 'LOAD|INTERP|STACK|DYNAMIC'

Что должно быть видно:
- readelf -r показывает 1308 R_X86_64_RELATIVE;
- readelf --dyn-syms показывает только нулевую запись, без экспортируемых символов;
- readelf -sW показывает blob_entry как локальный символ с адресом 0x8040;
- readelf -l не содержит INTERP, есть PT_LOAD, PT_DYNAMIC и GNU_STACK.

Как оформить:
Второй скриншот для проверки blob. Подпись в отчёте: «Рисунок 5 — Проверка релокаций, символов и сегментов blob-файла». Вставь сразу после рисунка 4.

РИСУНОК 6 — Сборка проекта

Где вставить: раздел 3.7, рисунок 6. В report.md: МЕСТО ДЛЯ РИСУНКА 6.

Команды:
make clean
make all
echo "rc=$?"

Что должно быть видно:
- сборка zlib, libpng и FreeType;
- сборка app-static, app-dynamic, app-blob и elfloader;
- код возврата 0.

Как оформить:
Полный лог может быть длинным. Покажи последние 25–35 строк, где видно завершение сборки и rc=0. Предупреждения zlib и FreeType можно оставить или обрезать, но в отчёте уже сказано, что они относятся к исходникам библиотек.

РИСУНОК 7 — Очистка проекта

Где вставить: раздел 3.7, рисунок 7. В report.md: МЕСТО ДЛЯ РИСУНКА 7.

Важно: этот рисунок делать последним, после рисунков 8, 9 и 10. Команда make clean удаляет build, после чего запускать app-static, app-dynamic и elfloader будет нечем. Если очистка уже сделана, перед следующими скриншотами снова выполни make all.

Команды:
make clean
test ! -d build && echo "build removed"
test ! -d app/object_files && echo "app object_files removed"

Что должно быть видно:
- build удалён;
- app/object_files удалён;
- команды проверки напечатали соответствующие сообщения.

Как оформить:
Одного короткого скриншота достаточно.

РИСУНОК 8 — Вывод трёх версий программы

Где вставить: раздел 3.8, рисунок 8. В report.md: МЕСТО ДЛЯ РИСУНКА 8.

Команды:
./build/app-static font.ttf out-static.png TRSPO
./build/app-dynamic font.ttf out-dynamic.png TRSPO
./build/elfloader build/app-blob font.ttf out-blob.png TRSPO

Что должно быть видно:
- для каждой версии строки load, zlib 1.2.11, total;
- у static и blob load равен 0.000000;
- у dynamic load заметно больше нуля;
- все три команды завершаются без ошибок.

Как оформить:
Перед скриншотом запусти dynamic два-три раза: первый запуск после сборки может показать load в несколько миллисекунд из-за холодного кеша, а в отчёте указан установившийся режим 0,14–0,23 мс. Затем сделай один скриншот с тремя запусками подряд. Если не помещается, можно сделать два скриншота: static + dynamic и blob.

РИСУНОК 9 — Проверка PNG-файлов

Где вставить: раздел 3.8, рисунок 9. В report.md: МЕСТО ДЛЯ РИСУНКА 9.

Команды:
file out-static.png out-dynamic.png out-blob.png
ls -l out-*.png
sha256sum out-*.png

Что должно быть видно:
- все три файла PNG, 202 x 106, 8-bit/color RGB;
- размер каждого файла 5669 байт;
- одинаковый SHA-256 у всех трёх файлов.

Как оформить:
Один скриншот. Если строки длинные, можно уменьшить шрифт терминала, но хеши должны читаться.

РИСУНОК 10 — Проверка обработки ошибок

Где вставить: раздел 3.8, рисунок 10. В report.md: МЕСТО ДЛЯ РИСУНКА 10.

Команды для программы:
./build/app-static; echo "rc=$?"
./build/app-static font.ttf; echo "rc=$?"
./build/app-static /no/such/font.ttf out.png TRSPO; echo "rc=$?"
./build/app-static font.ttf /proc/out.png TRSPO; echo "rc=$?"

Команды для загрузчика:
./build/elfloader; echo "rc=$?"
./build/elfloader /no/such/blob font.ttf out.png TRSPO; echo "rc=$?"
./build/elfloader report.md font.ttf out.png TRSPO; echo "rc=$?"
head -c 100 build/app-blob > /tmp/bad.elf
./build/elfloader /tmp/bad.elf font.ttf out.png TRSPO; echo "rc=$?"
./build/elfloader build/app-static font.ttf out.png TRSPO; echo "rc=$?"

Дополнительно, если хочешь показать отсутствие libz.so.1:
mkdir -p /tmp/nolibs
cp build/app-dynamic /tmp/nolibs/
cd /tmp/nolibs
./app-dynamic ~/Projects/gitrepo/trspo_labs/lab2/font.ttf out.png TRSPO
echo "rc=$?"
cd ~/Projects/gitrepo/trspo_labs/lab2

Что должно быть видно:
- сообщение usage при неверном числе аргументов;
- cannot open font при отсутствующем шрифте;
- cannot create png при недоступном пути;
- dlopen ... cannot open shared object file при отсутствии libz.so.1;
- для загрузчика: cannot open blob, el_init failed: not an ELF file, el_init failed: read error, el_relocate failed: bad relocation;
- во всех случаях rc=0.

Как оформить:
Можно сделать два скриншота: первый с ошибками app-static и отсутствием libz.so.1, второй с ошибками elfloader. Обязательно оставить строки с echo "rc=$?", чтобы был виден код возврата.

ДОПОЛНИТЕЛЬНО — размеры файлов

Если хочешь подтвердить таблицу 5 скриншотом, выполни:
size build/app-static build/app-dynamic build/app-blob build/elfloader

Этот скриншот не обязателен: данные уже есть в таблице 5. Если вставляешь, размести его рядом с таблицей в разделе 3.8 без отдельного номера рисунка.

ПОРЯДОК РАБОТЫ

1. Сделай финальную сборку make clean && make all.
2. Сделай рисунки 1, 3, 4, 5, 6, 8, 9 и 10.
3. Сгенерируй out.png и вставь его как рисунок 2.
4. Только после этого сделай рисунок 7 — очистку. Если после него понадобится ещё что-то запускать, снова выполни make all.
5. Вставь рисунки в report.md на места МЕСТО ДЛЯ РИСУНКА N.
6. Удали строки МЕСТО ДЛЯ РИСУНКА N, оставь подписи рисунков.
7. Оформи таблицы из report.md как таблицы Google Docs.
8. Проверь, что рисунки идут по порядку: 1 — структура, 2 — результат, 3 — зависимости, 4 — заголовок и динамическая секция blob, 5 — релокации и символы blob, 6 — сборка, 7 — очистка, 8 — запуск трёх версий, 9 — PNG-файлы, 10 — ошибки.
