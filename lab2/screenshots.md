Инструкция по скриншотам для отчёта по лабораторной работе № 2

Общие правила

1. Все команды выполняются из каталога проекта:
   cd ~/Projects/gitrepo/trspo_labs/lab2

2. Скриншоты делать после финальной сборки:
   make clean
   make all

3. Терминал: ширина 120–140 символов, шрифт 12–14 пт, одна тема оформления на все скриншоты. В кадре должны быть видны команда и её вывод. Пустые поля и лишние окна обрезать.

4. Если вывод длинный, показывать только нужную часть через head или tail, но так, чтобы было понятно, какая команда выполнялась. Нельзя обрезать строки с ошибками или кодами возврата.

5. В report.md места вставки отмечены строками МЕСТО ДЛЯ СКРИНШОТА N. После вставки изображения эти строки нужно удалить, а подпись рисунка оставить.

6. В report.md таблицы записаны простыми строками с разделителем |. В Google Docs их нужно оформить как таблицы: выделить строки и вставить таблицу, либо перенести данные вручную. Это не часть скриншотов, но лучше сделать сразу.

7. Рисунок 2 — это не скриншот, а сам файл out.png, полученный программой. Его нужно вставить в документ как изображение.

8. Значения времени в скриншотах могут отличаться от report.md: в отчёте указаны диапазоны по пяти запускам. Это нормально.

СКРИНШОТ 1 — Структура проекта

Куда вставить: раздел 3.1, рисунок 1.

Команда:
tree -L 2 -I 'object_files|objs' .

Что должно быть видно:
- каталоги app, elfloader, zlib, libpng, freetype, build;
- файлы Makefile, font.ttf;
- исходные файлы внутри app и elfloader.

Как оформить:
Скриншот можно обрезать по границам вывода tree. Строку с командой лучше оставить в кадре. Если дерево получилось слишком длинным из-за подкаталогов библиотек, можно показать только верхний уровень и содержимое app/elfloader: tree -L 1 . и tree -L 2 app elfloader.

СКРИНШОТ 2 — Зависимости статической и динамической версий

Куда вставить: разделы 3.3–3.4, рисунок 3.

Команды:
ldd build/app-static
ldd build/app-dynamic
readelf -d build/libpng.so | grep NEEDED
readelf -d build/libfreetype.so | grep NEEDED

Что должно быть видно:
- у app-static есть libm и libc, но нет libpng, libz, libfreetype;
- у app-dynamic есть только libc (и linux-vdso), без трёх библиотек;
- libpng.so и libfreetype.so содержат NEEDED libz.so.1.

Как оформить:
Можно сделать один длинный скриншот или два: первый с ldd, второй с readelf. Вставь оба под рисунок 3 или сделай коллаж. Главное, чтобы были видны и ldd, и NEEDED.

СКРИНШОТ 3 — Проверка ELF-файла blob

Куда вставить: раздел 3.5, рисунок 4.

Команды:
file build/app-blob
readelf -h build/app-blob | head -20
readelf -d build/app-blob
readelf -rW build/app-blob | awk '/R_X86_64/{print $3}' | sort | uniq -c
readelf --dyn-syms build/app-blob
readelf -sW build/app-blob | grep blob_entry
readelf -lW build/app-blob | grep -E 'LOAD|INTERP|STACK|DYNAMIC'

Что должно быть видно:
- file показывает ELF 64-bit, static-pie;
- readelf -h показывает Type DYN и Entry point 0x8040;
- readelf -d не содержит NEEDED;
- readelf -r показывает 1308 R_X86_64_RELATIVE;
- readelf --dyn-syms показывает только нулевую запись, без экспортируемых символов;
- readelf -sW показывает blob_entry как локальный символ;
- readelf -l не содержит INTERP, есть PT_LOAD, PT_DYNAMIC и GNU_STACK.

Как оформить:
Это самый важный набор скриншотов. Лучше сделать 2–3 скриншота: первый с file и readelf -h/-d, второй с релокациями и dynsym, третий с program headers. Вставь их подряд под рисунок 4. Не надо показывать весь вывод readelf -r: достаточно одной строки с count 1308.

СКРИНШОТ 4 — Сборка проекта

Куда вставить: раздел 3.7, рисунок 5.

Команды:
make clean
make all
echo "rc=$?"

Что должно быть видно:
- сборка zlib, libpng и FreeType;
- сборка app-static, app-dynamic, app-blob и elfloader;
- код возврата 0.

Как оформить:
Полный лог может быть длинным. Покажи последние 25–35 строк, где видно завершение сборки и rc=0. Предупреждения zlib про old-style function definition можно оставить или обрезать, но в отчёте уже сказано, что они относятся к zlib.

СКРИНШОТ 5 — Инкрементная сборка

Куда вставить: раздел 3.7, рисунок 6.

Команды:
touch app/funcs.c
make static
touch zlib/adler32.c
make static
make static

Что должно быть видно:
- после первого touch компилируется funcs.c и линкуется app-static;
- после второго touch пересобирается adler32.o, обновляется libz.a и приложение перелинковывается;
- после третьего make static нет компиляции, make пишет, что цель актуальна.

Как оформить:
Можно сделать два скриншота: первый для touch app/funcs.c и make static, второй для touch zlib/adler32.c, make static и повторного make static. Вставь оба под рисунок 6.

СКРИНШОТ 6 — Очистка проекта

Куда вставить: раздел 3.7, рисунок 7.

Важно: этот скриншот делать последним, после скриншотов 7, 8 и 9. Команда make clean удаляет build, после чего запускать app-static, app-dynamic и elfloader будет нечем. Если очистка уже сделана, перед следующими скриншотами снова выполни make all.

Команды:
make clean
test ! -d build && echo "build removed"
test ! -d app/object_files && echo "app object_files removed"

Что должно быть видно:
- build удалён;
- app/object_files удалён;
- команды проверки напечатали соответствующие сообщения.

Как оформить:
Одного короткого скриншота достаточно.

СКРИНШОТ 7 — Запуск трёх версий

Куда вставить: раздел 3.8, рисунок 8.

Команды:
./build/app-static font.ttf out-static.png TRSPO
./build/app-dynamic font.ttf out-dynamic.png TRSPO
./build/elfloader build/app-blob font.ttf out-blob.png TRSPO

Что должно быть видно:
- для каждой версии строки load, zlib 1.2.11, total;
- у static и blob load равен 0.000000;
- у dynamic load заметно больше нуля;
- все три команды завершаются без ошибок.

Как оформить:
Один скриншот с тремя запусками подряд. Если не помещается, можно сделать два скриншота: static + dynamic и blob.

СКРИНШОТ 8 — Проверка PNG-файлов

Куда вставить: раздел 3.8, рисунок 9.

Команды:
file out-static.png out-dynamic.png out-blob.png
ls -l out-*.png
sha256sum out-*.png

Что должно быть видно:
- все три файла PNG, 202 x 106, 8-bit/color RGB;
- размер каждого файла 5669 байт;
- одинаковый SHA-256 у всех трёх файлов.

Как оформить:
Один скриншот. Если строки длинные, можно уменьшить шрифт терминала, но хеши должны читаться.

СКРИНШОТ 9 — Проверка ошибок

Куда вставить: раздел 3.8, рисунок 10.

Команды:
./build/app-static; echo "rc=$?"
./build/app-static font.ttf; echo "rc=$?"
./build/app-static /no/such/font.ttf out.png TRSPO; echo "rc=$?"
./build/app-static font.ttf /proc/out.png TRSPO; echo "rc=$?"

Дополнительно, если хочешь показать отсутствие libz.so.1:
mkdir -p /tmp/nolibs
cp build/app-dynamic /tmp/nolibs/
cd /tmp/nolibs
./app-dynamic ~/Projects/gitrepo/trspo_labs/lab2/font.ttf out.png TRSPO
echo "rc=$?"
cd ~/Projects/gitrepo/trspo_labs/lab2

Что должно быть видно:
- сообщение usage при неверном числе аргументов;
- cannot open font при отсутствующем шрифте;
- cannot create png при недоступном пути;
- dlopen ... cannot open shared object file при отсутствии libz.so.1;
- во всех случаях rc=0.

Как оформить:
Один или два скриншота. Обязательно оставить строки с echo "rc=$?", чтобы был виден код возврата.

РИСУНОК 2 — Результат работы программы

Куда вставить: раздел 3.2, рисунок 2.

Команда:
./build/app-static font.ttf out.png TRSPO

Что вставить:
Не скриншот терминала, а сам файл out.png. Его можно открыть в просмотрщике изображений и убедиться, что на белом фоне написан текст TRSPO. В Google Docs вставить как изображение, ширину около 8–10 см.

ДОПОЛНИТЕЛЬНО — размеры файлов

Если хочешь подтвердить таблицу 6 скриншотом, выполни:
size build/app-static build/app-dynamic build/app-blob build/elfloader

Этот скриншот не обязателен: данные уже есть в таблице 6. Если вставляешь, размести его рядом с таблицей в разделе 3.8 без отдельного номера рисунка.

ПОРЯДОК РАБОТЫ

1. Сделай финальную сборку make clean && make all.
2. Сделай скриншоты 1, 2, 3, 4 и 5.
3. Сделай скриншоты 7, 8 и 9 — запуск, PNG и ошибки. Для них нужны собранные бинарники.
4. Сгенерируй out.png и вставь его как рисунок 2.
5. Только после этого сделай скриншот 6 — очистку. Если после него понадобится ещё что-то запускать, снова выполни make all.
6. Вставь скриншоты в report.md на места МЕСТО ДЛЯ СКРИНШОТА N.
7. Удали строки МЕСТО ДЛЯ СКРИНШОТА N, оставь подписи рисунков.
8. Оформи таблицы из report.md как таблицы Google Docs.
9. Проверь, что номера рисунков идут по порядку: 1 — структура, 2 — результат, 3 — зависимости, 4 — ELF blob, 5 — сборка, 6 — инкрементная сборка, 7 — очистка, 8 — запуск трёх версий, 9 — PNG-файлы, 10 — ошибки.
